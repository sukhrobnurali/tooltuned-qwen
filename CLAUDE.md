## Hard rule — no AI attribution

Per brief §16.2:

- Do **not** add `Co-authored-by:` of any AI assistant to commit messages, ever.
- Do **not** mention AI assistance, "generated by", or similar in commits, PRs, release notes, model card, or README.
- Do **not** sign commits with any non-author identity.

This is the discipline override for this repo. When committing here, never include the trailer that this CLI's default workflow adds elsewhere.

## Commit style (brief §16.4)

Lowercase imperative, terse. Variety is good. Examples that fit the project's tone:

```
init
add gitignore
wip: explore lr=2e-4
fix chat template padding
oops missed file
Update README with bfcl numbers
```

Mix lowercase / Capitalized occasionally. Avoid Conventional-Commits prefixes (`feat:`, `fix:`) — they read as ceremony, not work.

## Pre-push scan (brief §16.6 — zero hits required)

```bash
git log --all --grep="claude"     -i
git log --all --grep="anthropic"  -i
git log --all --grep="co-authored" -i
git log --all --grep="generated"  -i
git log --pretty=format:"%an <%ae>" | sort -u   # one line only
```

Any non-empty result → fix with `git rebase -i` / `git commit --amend` before pushing.

## Multi-session execution

Project is split one-phase-per-session. Memory carries state between sessions:
- `project_tooltuned_qwen.md` — current phase + next entry point
- `reference_tooltuned_qwen.md` — external resource URLs
- `feedback_session_handoffs.md` — the start/end-of-session checklists

At session start: read memory, run `git status` + `git log --oneline -10`, resume at documented entry point. At session end: update memory, run pre-push scan, append to session log.
